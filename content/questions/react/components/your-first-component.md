## Question
Write a `Counter` component that renders "Hello World", export it, and render it from `App`. What naming conventions apply, and what does `<Counter />` in JSX mean?

## Answer
```jsx
// src/components/Counter.jsx
export default function Counter() {
  return <h1>Hello World</h1>;
}
```

```jsx
// src/App.jsx
import Counter from './components/Counter'; // default export, so no braces

export default function App() {
  return <Counter />;                        // self-closing: no children
}
```

- **Component names start with a capital letter.** `<Counter />` is your
  component; a lowercase `<counter>` would be treated as an HTML tag.
- Put components in `src/components/`, one per file, using a `.jsx`
  extension (better editor support).
- An element with no children must be **self-closing**: `<Counter />`.

Using `<Counter />` is like **adding a new tag to HTML's vocabulary**:
wherever it appears, React renders whatever the component returns.

**Course vs today.** The course (2018) writes this as
`class Counter extends Component { render() { return <h1>…</h1>; } }`,
generated by the `imrc` + `cc` snippets. Function components are the
standard today.

## Key points
- a component is a function returning JSX
- component names are PascalCase; lowercase tags mean HTML elements
- export it, import it, render it as <Counter />
- empty elements must self-close in JSX
- old style: class extending Component with a render() method
